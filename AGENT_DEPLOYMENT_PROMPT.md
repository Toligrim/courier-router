Ты работаешь на Raspberry Pi 5 ARM64 с Ubuntu 25.10. Я передаю тебе ZIP проекта
courier-router. Твоя задача — развернуть его, проверить и довести до рабочего
состояния на этой машине, не меняя архитектуру без необходимости.

Главные правила:
1. Сначала прочитай README.md и INSTALL.md полностью.
2. Не ставь PostgreSQL, Redis, Chromium, Java, Rust, Nominatim или Pelias для MVP.
3. Используй Python 3.13 и отдельный `.venv`.
4. Установи проект `pip install -e '.[dev]'`.
5. Убедись, что OR-Tools импортируется нативно на aarch64.
6. Создай `.env` из `.env.example`. Никогда не коммить секреты и не печатай их в
   отчёте. Если ключей DaData/ORS нет, остановись на smoke-тестах локальных частей
   и явно перечисли, каких секретов не хватает.
7. Запусти `pytest -q`.
8. Запусти `courier-route doctor`.
9. Создай sample XLSX через `python scripts/make_sample_xlsx.py`.
10. Если API-ключи присутствуют, запусти `courier-route geocode-depot`, покажи
    оператору найденную каноническую запись и координаты. Не фиксируй координаты
    как проверенные без человеческой проверки.
11. Затем построй sample-маршрут и проверь наличие четырёх артефактов:
    itinerary.txt, route.json, route.png, geocoding-report.json.
12. Проверь PNG: он должен открываться Pillow, иметь ненулевой размер и содержать
    basemap/линию/нумерованные метки.
13. После cloud MVP можешь развернуть OSRM строго по INSTALL.md. Проверь manifest
    образа и отсутствие amd64-эмуляции. Затем прогони тот же маршрут с ROUTER=osrm
    и сравни порядок/дистанцию.
14. Не включай LLM, пока маршрут без LLM не работает. После этого, если есть ключ,
    протестируй один искусственно грязный адрес с OpenAI или Anthropic.
15. Не отправляй в LLM телефоны, суммы платежей и полный Excel.

Если обнаружишь баг:
- сначала добавь воспроизводящий тест;
- затем исправь минимально;
- снова прогони весь pytest;
- не заменяй OR-Tools на LLM и не переносись на Node.

В финальном отчёте дай:
- архитектуру/версию ОС/архитектуру CPU;
- Python и версии ключевых пакетов;
- результаты тестов;
- результат doctor;
- какие API реально проверены;
- какие файлы создал sample run;
- отдельный статус OSRM;
- найденные проблемы/изменения;
- точные команды для боевого запуска.
