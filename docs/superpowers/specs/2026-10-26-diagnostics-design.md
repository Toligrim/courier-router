# Постоянные логи и понятные ошибки

Нужен разбор сбоев Courier Router после события: от загрузки таблицы до
геокодирования, расчёта и сохранения маршрута. Пользователь видит причину,
следующее действие и номер обращения, а технические детали остаются в журнале.

## Выбранная схема

Мой инженерный выбор для существующего VPS: стандартный Python logging,
построчный JSON в `/var/log/courier-router/application.jsonl`, 5 архивов по
5 MiB и активный файл до 5 MiB (примерно 30 MiB всего). Системный journal
сохраняет сведения о запуске и сбоях процесса. Отдельные база, контейнер и
внешний сервис требуют дополнительных ресурсов и здесь не нужны.

В событиях: UTC, уровень, событие, request_id, run_id, этап, длительность,
номер строки, поисковый адрес без квартиры, кэш, попытка, ответ провайдера,
тип ошибки и traceback без локальных переменных. Контекст передаётся в
рабочие потоки; параллельные запросы не смешиваются. Секреты маскируются;
тела запросов, cookies, телефоны, оплаты и целые таблицы не записываются.
Права каталога 0750, файла 0600; логи переживают перезапуски приложения и VPS.
Сбой записи лога не должен останавливать построение маршрута: аварийный
канал — stderr/journal. Используется один процесс web, один writer файла.

Геокодер различает timeout, unavailable, blocked, extraction и not_found.
Технические ошибки не кэшируются как отсутствующий адрес. Ожидание координат
увеличено до 20 секунд, сетевой timeout повторяется один раз. Проверки
соответствия улицы, дома и региона сохраняются. Пустой непонятный ответ
не считается доказательством отсутствия дома.

В интерфейсе timeout: «Не удалось дождаться ответа сервиса карт. Попробуйте
построить маршрут ещё раз через минуту». Указывается строка таблицы, если
она известна, и номер ошибки. Неожиданная ошибка получает общее сообщение;
traceback, Playwright и внутренние пути в HTML не попадают. Ошибки формата
таблицы сохраняют полезные сведения о строке/колонке.

## Готовность

Тесты проверяют ротацию, корреляцию и изоляцию контекста, редактирование
секретов, отказ файловой записи, корректные категории ошибок, отсутствие
ошибочного negative cache, повтор timeout, чистый HTML и успешные маршруты.
Независимое read-only ревью обязательно. На VPS развёртывается новый каталог
релиза с откатом через systemd drop-in; прежнее venv сохраняется. Проверяются
health, реальный файл и чтение сохранённой ошибки по её номеру. Операционные
команды и ограничение хранения описываются в runbook.
