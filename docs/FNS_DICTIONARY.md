# Справочник улиц ФНС и Яндекс Карты

Справочник используется для исправления однозначных опечаток в названии улицы.
Координаты по-прежнему получает Яндекс через headless Chromium. Исходный адрес,
дом, корпус, строение и литера сохраняются. Нормализация работает локально.

## Источник и загрузка

Официальные метаданные:
https://fias.nalog.ru/WebServices/Public/GetLastDownloadFileInfo

Используются `VersionId`, `Date`, `GarXMLFullURL`. Из полного ZIP выборочно читаются
`47/AS_ADDR_OBJ_*.XML`, `78/AS_ADDR_OBJ_*.XML` и соответствующие
`AS_ADM_HIERARCHY_*.XML`. Архив поддерживает ZIP64. HTTP Range позволяет получить
эти файлы без загрузки всей страны. Для выпуска 20261020 это примерно 116 МБ
сжатых данных плюс каталог ZIP и округление диапазонов. Иерархия распаковывается
потоково; многогигабайтные XML целиком на диск или в память не загружаются.

Каждый выпуск собирается заново из полного снимка. Пропущенные выпуски не требуют
цепочки дельт. Если ФНС перестанет поддерживать Range, загрузка завершается
ошибкой, сохраняя текущую базу. Автоматического скачивания всего 58-ГБ архива нет.
Обрыв тела ответа повторяет загрузку отдельного блока до трёх попыток с паузой;
неполные блоки не используются. Повторно полученные байты также учитываются
в ограничении объёма загрузки. При исчерпании попыток текущая база сохраняется.

```bash
courier-route dictionary update
courier-route dictionary status
courier-route dictionary normalize 'СПб, ул Горохвая, д 68 кв 20'
```

Каталог задаётся `ADDRESS_DICTIONARY_DIR=data/cache/address-dictionary` либо
`--root` после подкоманды. Для заранее скачанного **полного** архива:

```bash
courier-route dictionary update --archive /path/to/gar_xml.zip --version 20261020
```

Первая установка не скачивает базу во время построения маршрута: обновляющий
процесс запускается отдельно. Пока базы нет, работает обычный поиск Яндекса.
Пустое `ADDRESS_DICTIONARY_DIR` отключает справочник. Повреждённая активная база
даёт явную ошибку, а не незаметное изменение алгоритма.

## Правила нормализации и проверки

- Сохраняется актуальная и действующая запись объекта (`ISACTUAL=1`, `ISACTIVE=1`).
- Улица относится к региону через проверенную административную иерархию.
  Улицы с неполной или циклической цепочкой родителей исключаются и учитываются
  в `excluded_orphans`; массовая потеря связей блокирует выпуск.
- Разбирается явно обозначенная улица (`ул`, `проспект`, `линия` и другие типы).
  Для неразобранного адреса сохраняется обычный поиск Яндекса.
- Учитываются указанные населённые пункты и территории. Колонка «район курьера»
  не используется как жёсткое ограничение справочника.
- Точное совпадение имеет приоритет. Для исправления нужны известная территория,
  совпадающий тип улицы, небольшое число правок и отрыв от второго кандидата.
  При неизвестной территории или неоднозначности строка не меняется.
- Числа в названии и слова вроде «Большая/Малая» защищены от нечёткого исправления.
  Тип улицы и номера линий также проверяются после получения карточки Яндекса.
- Для координат читается видимое поле карточки. Первые произвольные
  `coordinates` в HTML больше не используются.

В `geocoding-report.json` сохраняются `dictionary_version`, `normalization`
(исходная и подготовленная строка, статус, ID объекта, варианты и исправление).
Это технический отчёт: в самом маршруте остаётся исходный адрес курьера.

Кэш итогового геокодирования учитывает версию справочника и нормализатора.
При новой версии результат пересчитывается; при том же поисковом запросе
карточка Яндекса может быть взята из отдельного кэша. Ручные закрепления
координат остаются приоритетными и хранятся в прежней базе приложения.

## Публикация, ротация и откат

Структура каталога:

```text
address-dictionary/
  .update.lock
  .publish.lock
  status.json
  releases/<version>-<build-id>/streets.sqlite
  releases/<version>-<build-id>/manifest.json
  current -> releases/<version>-<build-id>
```

Один обновляющий процесс строит новую базу во временном каталоге. До публикации
проверяются CRC выбранных ZIP-файлов, целостность SQLite, оба региона, минимальное
число улиц, изменение объёма относительно предыдущей версии и контрольные адреса.
Манифест содержит ссылку на источник, версию, статистику, CRC файлов источника и
SHA-256 собранной базы. База полностью закрывается и синхронизируется на диск;
указатель `current` заменяется атомарно в пределах одной файловой системы.

Приложение под короткой общей блокировкой загружает снимок в память при создании
геокодера. Весь маршрут использует одну версию. Обновляющий процесс берёт
исключительную блокировку только для публикации и очистки: уже загруженные
снимки продолжают работать и после удаления старого файла.

Сохраняются активный и два предыдущих пригодных снимка; отменённые выпуски
не вытесняют рабочие версии из истории. После переключения выполняется
повторная проверка открытия базы. При её ошибке указатель автоматически
возвращается назад, а выпуск попадает в `blocked_versions`. Ручной откат:

```bash
courier-route dictionary rollback
```

Он также блокирует отменённый выпуск от автоматического повторного включения.
Следующая новая версия ФНС может быть установлена обычным обновлением. Ошибки
загрузки или проверки до переключения оставляют действующий справочник активным.
Следующая ночная попытка повторяет незавершённую загрузку; промежуточные каталоги
после аварий очищаются под блокировкой обновления.

`dictionary status` показывает активный манифест, время проверки и успеха,
доступную версию, последнюю ошибку и заблокированные выпуски. Источник истины
для активной версии — `current`, а не вспомогательное поле `status.json`.

## Ночное обновление на сервере

В патч входят `ops/courier-router-dictionary.service` и `.timer`. Пути и
пользователь соответствуют существующему развёртыванию в `courier-router`.
Перед установкой на другой машине адаптируйте их. Для отдельного worktree
нужно также изменить рабочий каталог и путь к установленной команде.

После установки кода, зависимостей и первой успешной загрузки:

```bash
sudo install -m 644 ops/courier-router-dictionary.service /etc/systemd/system/
sudo install -m 644 ops/courier-router-dictionary.timer /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now courier-router-dictionary.timer
systemctl list-timers courier-router-dictionary.timer
journalctl -u courier-router-dictionary.service
```

Таймер запускает проверку в 04:00 по Москве с разбросом до десяти минут.
`Persistent=true` обеспечивает запуск пропущенной проверки после включения
сервера. Сервис имеет ограничение в час и пониженный приоритет. Он не
перезапускает веб-приложение: новые маршруты сами подхватывают новую версию.

## Проверки

```bash
ADDRESS_DICTIONARY_DIR='' pytest -q
```

Тесты используют маленькие ZIP с настоящей структурой XML ГАР и локальный
HTTP-транспорт. Проверяются нормализация с географическим контекстом,
неоднозначность, защищённые компоненты, работа с Яндексом и кэшем, импорт,
повреждённые ответы сервера, конкурентный запуск, публикация, ротация и откат.
Живые запросы в ФНС/Яндекс выполняются отдельно от автоматических тестов.

### Первая проверка на настоящей выгрузке — 21.10.2026

Выпуск `20261020` успешно собран из официального архива: 41 982 записи уличной
сети региона 47 и 4 999 региона 78. Улиц с неполной иерархией не обнаружено,
CRC, целостность SQLite и контрольные адреса прошли проверку. Готовый каталог
занимает около 9,5 МБ. Повторный запуск вернул `up_to_date` без повторного импорта.

На этой базе `СПб, ул Горохвая, д 68 кв 20` преобразуется в
`Санкт-Петербург, улица Гороховая, д 68`. Живой headless Chromium получил карточку
Гороховой, 68 (`59.922580, 30.331319`), итоговый статус — `verified`.
Опечатка `Совесткая` во Всеволожске исправляется в `Советская`; без населённого
пункта она остаётся неоднозначной. Неизвестная деревня и неизвестный населённый
пункт с цифры блокируют автозамену.
Живая карточка Советской, 5 во Всеволожске (`60.009094, 30.608279`) также прошла
проверку со статусом `verified` после нормализации опечатки.

При живом запросе Советской, 1 во Всеволожске Яндекс вернул Советскую, 5:
проверка дома выставила `strong_mismatch`, поэтому такой результат не будет
принят маршрутом как правильная координата.
Один из повторных браузерных запросов не вернул результат; последующая проверка
прошла. Доступность внешней страницы Яндекса не гарантируется: при отсутствии
карточки геокодер сообщает ошибку и не придумывает координаты.

Полный автоматический набор: 329 тестов прошли; независимое read-only ревью
после исправлений — без замечаний. Systemd-проверка обеих единиц прошла.
